# Next version — what makes this the best CLM team in the industry

Research date: 2026-09-10. Sources at the end. Scored with ICE (impact × confidence × ease, 1–10 each).

## Where the industry is (and where we already are)
- **Incrementality is the measurement standard.** Platform-reported CTR is no longer defensible; teams run 10–20% randomized holdouts on every lifecycle message and pre/post only for big releases ([Simon Data](https://www.simondata.com/blog-posts/measuring-incrementality-crm-marketing), [Measured](https://www.measured.com/faq/what-is-incrementality-in-marketing/), [Improvado](https://improvado.io/blog/marketing-lift)). *We have:* holdout in every brief, an experiment ledger with Wilson intervals, QA that flags drafts without holdouts. *Gap:* our readouts are pre/post because the stats API exposes no control-group figures; MoEngage's **global control group** API exists (`update_global_control_group`) and campaign meta v5 may carry control stats — verify on the live workspace.
- **Event-triggered beats scheduled.** The leading platforms (Braze Decisioning Studio, Iterable Nova) push decisioning to the moment: channel, variant, timing and frequency chosen per user from live signals ([Braze](https://www.braze.com/resources/articles/agentic-ai-marketing), [BusinessWire](https://www.businesswire.com/news/home/20260423931363/en/Braze-Delivers-Powerful-New-Agentic-AI-Capabilities-That-Transform-How-Marketers-Build-Personalize-and-Deliver-Customer-Experiences)). *We have:* the best market-signal brain in the category (regime, flow, listings, OI, funding, rivals) but it reaches users through **scheduled** proposals. *Gap:* MoEngage **Business Events** are built exactly for this: an external system fires an event, MoEngage runs the campaign per user ([MoEngage Business Events](https://www.moengage.com/docs/api/business-events/business-events-overview), [Trigger API](https://developers.moengage.com/hc/en-us/articles/17150140786964-Trigger-Business-Event-API)). Our client already has `business_event_trigger`.
- **Predictive layer belongs to the platform.** MoEngage Sherpa does per-user send-time, churn probability and content affinity; Merlin is the generative/agentic layer ([Field notes 2026](https://medium.com/@aveggiani/2026-field-notes-on-customer-engagement-platforms-part-7-moengage-505a7033c35d), [Sherpa](https://www.moengage.com/blog/introducing-sherpa-by-moengage/)). *Implication:* do not rebuild STO/churn models locally; make every proposal **use** Sherpa (best-time delivery, churn-score segments) and keep our edge where the platform is blind: market context, India compliance, cohort nomenclature, competitive intel.
- **Crypto's problem is activation, not acquisition.** Only 6–10% of owners are monthly active and 14–27% of those trade; personalised insights and tiered fee programmes are what the leaders retain with ([PLG Insider](https://medium.com/the-plg-insider/cryptos-user-activation-crisis-a-product-case-study-on-coinbase-s-activation-funnel-e2a21b6eef48), [GuerrillaBuzz](https://guerrillabuzz.com/blog/crypto-exchange-marketing-strategy)). *We have:* the structural P0 journeys and fee-tier nudges as SOPs. *Gap:* per-user "own numbers" content (P&L, fees saved, alerts hit) needs a **Content API** source or user attributes we write.

## Shipped in this version
- **Signal Bridge** (`backend/signals.py`): catalog of signals detected from the cached context; standing rules approved through the normal queue (proposal kind `signal_rule`); evaluation on every context refresh; per-rule daily cap, quiet hours (IST) and regime policy; fires through `business_event_trigger` (mock mode records the fire only); ledger; Engine → Signal bridge panel; tools `signal_catalog`, `propose_signal_rule`, `signal_fires`.
- **Compliance sweep** (`backend/compliance_sweep.py`): every live campaign's content preview linted; findings by severity with the exact rule; QA check `live_copy_compliant`; tool `compliance_sweep`; Analysis → Compliance panel.
- **Own-learnings skill** (`backend/learnings.py`): readouts → `.claude/skills/our-learnings/SKILL.md`, refreshed in the daily cycle; the agent loads it like any skill.
